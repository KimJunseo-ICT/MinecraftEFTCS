# 모드 전용 인벤토리

## 열기와 전환

- 서바이벌·어드벤처에서 `E`를 누르면 전용 장비 화면을 엽니다.
- 크리에이티브에서는 기존 인벤토리의 **서바이벌 보관함** 탭 왼쪽에 있는 `E` 버튼으로 전용 화면에 들어갑니다. 버튼에 커서를 올리면 전환 설명이 표시됩니다.
- 전환 전에 일반 인벤토리·핫바·왼손·서버가 관리하는 커서와 기존 근접무기 칸의 무기를 합산합니다. 주무기 2정·보조무기 1정·근접무기 1개를 초과하면 수량 안내와 함께 전환을 거부하며, 물품과 기존 모드는 그대로 유지합니다. 통과하면 무기를 지정 장비 칸에 자동 배치하고 밀려난 일반 물품도 보존합니다. 가방과 케이스 내부 보관물은 이 착용 수량 검사에서 제외합니다.
- 전용 화면 좌측 상단의 **크리에이티브로 전환** 버튼으로 기존 화면에 돌아갑니다. 선택은 플레이어별로 저장합니다.
- 크리에이티브에서 기존 인벤토리를 사용 중이면 개인 창고의 문과 `I` 단축키 모두 열기를 거부하고 `인벤토리를 모드 인벤토리로 교체해주세요.`를 표시합니다.
- 개인 창고와 설치형 무기 케이스에서는 군번줄·바이탈 구역을 생략하고 캐릭터·방어구·무기 구역을 좁혀 배치합니다. 군번줄 데이터는 그대로 유지됩니다. 오른쪽 소지품 영역과 창고·케이스 영역은 각각 별도로 스크롤합니다.
- 개인 창고는 한 번에 13행(130칸)을 표시해 아래쪽 여백을 줄입니다. 설치형 케이스는 실제 행 수 범위까지만 표시합니다. 케이스 이동 제한 안내는 장비 제목 오른쪽 위에 따로 표시하며, 모든 아이템 설명과 이미지 구성요소는 장비 아이콘·케이스 팝업보다 위에 표시합니다.
- 케이스 팝업이 열려 있으면 `ESC` 또는 인벤토리 키(기본 `E`)는 팝업만 닫습니다. 키를 놓고 다시 누르면 전체 인벤토리가 닫힙니다. 케이스 닫기 자체로 손에 집은 물품을 반납하거나 인벤토리 메뉴를 종료하지 않습니다.
- 격자에 놓인 물건은 위쪽·왼쪽 외곽선까지 포함해 그려 기존 칸 경계가 남지 않도록 합니다. 창고·케이스와 장비 칸 사이에서 집어 옮기는 총기는 회전·부착물이 반영된 같은 3D 미리보기를 사용하며, 커서 표시는 각 격자의 잘라내기 범위 밖에서 한 번만 그립니다.
- 우측 상단의 `휠로 스크롤` 문구를 없애고, 총기·케이스를 집은 동안 해당 자리에 `R: 90도 회전`을 표시합니다. 장비 단축키 버튼은 구역 상단·우측 테두리에 붙이며, 핫바의 연두색 선택 표시는 숫자 아래인 칸 하단에 표시합니다.

## 슬롯과 키

| 구분 | 키 | 허용 아이템 |
|---|---|---|
| 보조무기 | `1` | TACZ의 권총 카테고리 |
| 주무기 1·2 | `2`·`3` | TACZ 권총을 제외한 총기 |
| 주머니 6칸 | `4`~`9` | 일반 소지품. 총기·검·도끼·삽·곡괭이·괭이는 금지 |
| 왼손 | `F` | 기존 마인크래프트 왼손 칸 |
| 근접무기 | `U` | 검, 도끼, 삽, 곡괭이, 괭이 |
| 방어구 | — | 기존 머리·상체·하체·발 장비 칸 |
| 군번줄 | — | 캐릭터에게 자동 지급되는 본인 군번줄 |
| 가방·보안 컨테이너 | — | 해당 종류의 저장 장비 |

`U`는 실제 주 손에 근접무기를 꺼내므로 공격과 채굴에 사용할 수 있습니다. 다시 `U`를 누르거나 다른 번호를 선택하면 이전 무기로 돌아갑니다. 선택했던 무기와 근접무기는 로그아웃·화면 열기·사망·플레이어 복제 과정에서 각각 보존하거나 정상 드롭하도록 처리합니다. 핫바에 `U` 전용 표시가 추가되며 `1`~`9` 할당은 유지합니다.

무기와 왼손 구역은 제목과 키를 분리해, 우상단 작은 버튼 모양에 현재 설정된 단축키를 표시합니다. 번호키 교환·Shift 이동·아이템 줍기도 주머니의 무기 제한을 따릅니다. 가방·보안 컨테이너 안에 무기를 보관하는 기능은 유지합니다.

왼손 `F` 칸도 총기와 근접무기를 거부하며, 클릭 배치와 `F` 교환 모두 같은 제한을 적용합니다. 기존 왼손 무기는 규칙 업그레이드 시 지정 장비 칸·저장 장비·회수 영역 순서로 보존합니다. 개인 창고, 대형·일반·특수 3종 케이스와 설치형 케이스에서 꺼낸 무기는 지정 장비 칸에 다시 착용할 수 있습니다. 장비 필터는 메뉴 전체 번호와 실제 핫바 번호를 구분하고, 팝업의 동기화 전용 위치는 열린 케이스의 유효한 칸에 한해 클릭을 허용합니다.

아이템은 클릭으로 집어서 옮깁니다. 우클릭은 한 개 놓기·나누기, Shift+클릭은 빠른 이동입니다. 가방·보안 컨테이너에서도 기존 창고와 같은 총기 크기 계산을 사용하고, `R`로 집은 총기·케이스를 회전할 수 있습니다. 배치 가능 위치는 녹색, 불가능한 위치는 빨간색입니다. 서버에서도 동일한 직사각형 공간을 검사합니다.

## 군번줄과 체력

- 아이템 ID: `minecrafteft:basic_dogtag`. 체인과 은색 식별판을 Minecraft 기본 재질을 쓰는 3D 모델로 구성했습니다.
- 최초 접속과 재스폰 때 캐릭터에게 군번줄을 지급하며 소유자 UUID·이름·발급 시점을 저장합니다. 현재 본인 장비 칸에서 빼는 기능은 막고, 사망 시 드롭되는 아이템으로 남겨 향후 시체 루팅에 연결할 수 있게 했습니다.
- 일반 장비 화면의 군번줄은 캐릭터 창 왼쪽 상단에 정렬합니다. 그 아래 확대한 바이탈 창은 심전도 → `(현재 / 최대 체력)` 숫자 → 체력 게이지 → 에너지 게이지 → 수분 게이지 순서입니다. 체력 숫자는 심전도 아래·체력 게이지 위에 가운데 정렬하고, 에너지·수분은 기존 아이콘과 퍼센트를 함께 표시합니다.
- 플레이 화면 좌측 하단 HUD에는 체력과 그 바로 아래 스태미나 두 줄만 표시합니다. 에너지·수분은 장비 화면에서 확인하며, 플레이 화면의 스태미나 위치는 기존 에너지 줄과 같습니다. 기존 체력·스태미나 표시 보간과 수치 계산은 유지합니다.
- 바이탈 선은 체력 50% 초과에서 녹색 안정, 20% 초과~50%에서 노란색 주의, 20% 이하에서 빨간색 위험입니다. 안정은 느리고 일정한 둥근 파형(표시용 66회/분), 주의는 더 빠르고 높으며 깊은 파형(108회/분), 위험은 더 촘촘하고 박동 간격·강도가 변하는 파형(156회/분)입니다. 동일한 2초 구간을 보여 주며 각 화면 픽셀 안의 최솟값·최댓값을 보존해 빠른 봉우리도 빠지지 않습니다. 창에 상태 이름도 표시합니다. 실제 피해나 생체 시뮬레이션을 바꾸는 수치는 아닙니다.
- 바이탈 왼쪽 선을 주무기 칸에 맞추고, 군번줄·캐릭터·방어구의 위쪽 선과 바이탈·캐릭터·방어구의 아래쪽 선을 정렬합니다. 주머니 영역은 위쪽 선을 다른 장비 창과, 아래쪽 선을 마지막 무기 행과 맞춥니다.
- HUD 두 줄은 채팅 이력 아래·입력창 위의 빈 구간에 고정합니다. 좁은 GUI에서는 게이지 너비를 줄이고 위쪽으로 밀어 올리지 않습니다. 플레이·채팅 화면에서는 채팅 글자보다 앞에 그려져 기존 채팅 깊이에 가려지지 않습니다.
- 기본 체력 재생은 차단합니다. 허기·평화로움 난이도·바닐라 재생 및 회복 효과나 일반적인 `heal()` 호출로 독립 체력이 올라가지 않습니다. AI-2·IFAK 직접 치료는 `VitalEvents.healWithTreatment`로 적용합니다. 향후 모드 전용 재생 버프를 구현하기 전에는 자동 재생 경로를 두지 않습니다. 재스폰과 기존 생명 보존 처리는 별도입니다.

## 가방·보안 컨테이너 확장 지점

첫 배낭인 `minecrafteft:lbt_8005a_day_pack`은 가로 4칸·세로 5칸입니다. 손에 들고 우클릭하면 장비 화면 옆에 내부 20칸을 엽니다. 여는 동안 손의 배낭은 클릭·Shift 이동·번호키/F 교환으로 옮길 수 없고, 배낭 내부에 저장 장비를 중첩할 수도 없습니다. 닫은 뒤에도 내용물은 배낭과 함께 이동합니다. 개인 창고에 둔 배낭은 기존 팝업으로 열 수 있습니다.

장착 배낭과 손에 든 배낭 모두 총기 크기·회전에 맞춰 직사각형 공간을 검사합니다. 커서 중심을 기준으로 배치 위치를 계산하며, 가능/불가능 표시와 실제 클릭이 같은 칸을 가리킵니다. 향후 아이템 클래스에서 `StorageEquipment` 인터페이스의 종류(`backpack` 또는 `secure`), 가로 칸 수와 세로 칸 수를 제공하면 착용·표시·보관을 확장할 수 있습니다. 현재 상한은 가로 8칸, 세로 20칸입니다.

물건이 이미 차지한 칸은 시작 칸까지 포함해 새 배치를 거부합니다. 무기가 겹치면 배치 불가로 표시하고, 클릭·우클릭·숫자키 교환으로 기존 무기와 바꾸지 않습니다. 먼저 기존 무기를 꺼낸 뒤 확보한 빈 직사각형 공간에 다시 넣어야 합니다. 이 규칙은 장비 화면·개인 창고의 장착 배낭, 손에 든 배낭 화면, 창고 안 배낭 팝업에 공통으로 적용합니다. 같은 일반 소모품의 1×1 묶음 합치기는 허용합니다.

내용물은 플레이어의 별도 가상 창고가 아니라 **장비 아이템 자체의 NBT**에 저장됩니다. 장비를 벗으면 해당 격자는 사라지고 내용물은 장비와 함께 이동합니다. 저장 장비를 다시 그 안에 넣는 중첩은 막습니다. 배낭은 일반 플레이어와 지원 YSM 모델의 등에 표시하며 가방 외형 숨기기 토글을 따릅니다.

정식 장비를 만들기 전 테스트를 위해 다음 NBT 표식도 지원합니다.

```mcfunction
/give @s minecraft:chest{MinecraftEFTStorage:{Kind:"backpack",Width:4,Height:5}}
/give @s minecraft:ender_chest{MinecraftEFTStorage:{Kind:"secure",Width:3,Height:3}}
```

위 아이템을 각각 가방·보안 컨테이너 칸에 넣으면 확장 격자가 표시됩니다. 이는 테스트용 표식이며 손에 들고 우클릭하는 기능은 등록된 Day Pack에 적용됩니다. 현재 사망 시 장비와 내용물은 기존 `keepInventory` 규칙을 따릅니다.

## 기존 아이템과 저장

시체를 가리켜 실제 엔티티 상호작용 대상으로 잡히고 시체를 열 수 있는 거리·상태이면 크로스헤어 아래에 **우클릭으로 상호작용**을 표시합니다. 상호작용 거리는 플레이어와 시체 위치 기준 **2.5블록 이내**이며 크리에이티브에서도 동일합니다. 안내 문구·우클릭 열기·열린 창의 유효성 및 아이템 이동에 같은 거리 조건을 적용합니다. 벽 너머나 범위 밖, 메뉴가 열린 상태에서는 안내를 표시하지 않습니다.

시체 안내의 등록 클래스와 메서드는 핫바 등록 함수와 다른 고유 이름을 사용합니다. Forge 47.4.10의 이벤트 버스에서 내부 클래스의 짧은 이름·메서드 이름·이벤트 종류가 같으면 서로 다른 콜백이 같은 중간 클래스를 재사용해 핫바를 중복 등록할 수 있습니다. `EventSubscriberNamesCheck`는 완성된 JAR의 모든 이벤트 함수에서 이 이름 충돌을 게임 실행 없이 검사합니다.

시체 외형과 시체 화면의 캐릭터 미리보기에는 손의 무기·외부 방어구·배낭을 표시하지 않습니다. 스킨·YSM 모델과 사망 자세는 유지하며, 외형 표시를 숨기는 처리는 시체의 장비·배낭 내용물 데이터를 바꾸지 않습니다.

시체의 배낭·보안 컨테이너 다중 칸 아이템은 다른 가방 화면과 같은 회전 미리보기를 사용합니다. R 키로 회전한 무기는 점유 영역뿐 아니라 무기 모습도 90도 돌아가며, 고정 장비 칸의 미리보기는 기존 방향을 유지합니다.

임시 군번줄 테스트: 플레이어가 좀비 주민을 사살하면 기록이 담긴 기본 군번줄 1개를 기존 드롭에 추가합니다. 좀비 주민의 UUID·이름(이름표 포함), 레벨 1, 사망 시각, 실제 사살자와 TACZ 총기 ID 또는 일반 사망 원인을 기존 시체 군번줄 형식으로 저장합니다. 자연사와 다른 몹은 대상이 아닙니다. 획득한 군번줄에 커서를 대고 Shift를 누르면 세부 사항을 볼 수 있습니다. 각 월드의 `serverconfig/minecrafteft-corpse-test-server.toml`에서 `zombieVillagerDogtags = false`로 설정하면 테스트 드롭을 끌 수 있습니다(초기값 `true`). 플레이어 시체 생성·기존 군번줄 발급·일반 몹 드롭은 기존 처리를 유지합니다.

시체의 군번줄 칸은 꺼내기만 가능하고 근접무기 칸은 기존 읽기 전용 표시를 유지합니다. 다른 장비 칸과 배낭·보안 컨테이너에는 슬롯 종류와 직사각형 빈 공간 조건에 맞는 아이템을 다시 넣을 수 있습니다. Shift+클릭도 플레이어→시체와 시체→플레이어 양쪽으로 이동하며, 공간이 부족하면 남은 물품은 원래 칸에 보존합니다. 열어 둔 동안 회수한 추가 보관 칸은 빈 상태로도 남아 일반 물품을 다시 놓을 수 있습니다.

기존 핫바·27칸 인벤토리 물품을 전용 구조로 처음 전환할 때, 새 소지 공간에 못 들어가는 물품은 오른쪽 스크롤 영역 아래의 **이전 인벤토리 물품 회수**에 보존합니다. 이 영역은 꺼내기 전용이며 비우면 사라집니다. 전환 후에는 기존 27칸을 숨겨진 추가 가방처럼 사용하지 않습니다. 새로 획득한 물품은 무기·주머니·장착 저장 장비에 들어가며 공간이 없으면 바닥에 남습니다.

이전 빌드에서 주머니에 넣어둔 무기는 새 규칙 적용 시 전용 장비 칸·장착 저장 장비로 이동하고, 여유 공간이 없으면 회수 영역으로 옮깁니다. 회수 영역까지 꽉 찬 경우에는 기존 초과 물품 처리처럼 플레이어 근처에 드롭합니다.

네트워크 프로토콜은 13이며 클라이언트와 서버에 같은 모드 빌드가 필요합니다. 장비와 전환 상태는 플레이어 capability로 저장하고 서버가 동기화합니다.

사망·리스폰 전환 중 무효화된 플레이어 정보를 HUD와 배낭 외형이 강제로 읽지 않습니다. 플레이어 복사 시에는 새 capability 핸들로 기존 장비·설정을 안전하게 읽고, 사망 복사와 차원 이동 복사에 맞는 보존 규칙을 적용합니다.

크리에이티브 카테고리 영역 위의 휠 입력은 카테고리 목록에 우선 전달합니다. 아이콘 13종은 제공된 원본 해상도 파일을 그대로 사용하며, 표시할 때만 어두운 선의 투명도와 가장자리 필터를 적용합니다. 32×32로 축소하거나 아이콘 모양을 다시 그리지 않습니다. 리소스를 다시 불러오면 표시 캐시도 갱신합니다.

## 검증 범위

`InventoryGridCheck`의 직사각형 충돌·회전·경계 검사와 `InventoryVitalWaveformCheck`의 파형 경계·연속성·박동 밀도 검사를 게임 실행 없이 통과했습니다. 서버 테스트에는 장비 필터, 기존 물품 수량 보존, 가방 탈착·NBT 저장, 회전 삽입, 근접무기 왕복, 주머니 규칙 업그레이드, 숫자키 제한과 기본 회복 차단 검사를 포함했으며 컴파일만 확인합니다. 실제 게임 클라이언트나 GameTest 서버를 자동 실행하지 않습니다.

상태 구분을 강화한 `InventoryVitalWaveformCheck`는 82,313개 검사를 통과했습니다. 상태별 박동 수·진폭·위험 상태의 강약 변화와 실제 74픽셀 창에서 봉우리가 유지되는지를 확인합니다.

`WeaponSlotAllocationCheck`는 모든 6칸 무기 조합과 스택 수량, 왼손 이동, 기존 장비 위치 유지를 포함한 15,617개 검사를 게임 없이 실행합니다. 추가 서버 테스트는 케이스 5종 각각의 팝업·설치형 추출→착용, 창고 왕복과 NBT 보존, 왼손 클릭·교환 제한, 가방 마지막 유효 칸 클릭, 크리에이티브 초과 수량의 원자적 거부와 정상 자동 배치를 검사하도록 작성했으며 컴파일만 확인합니다.

ver4에서는 `BagPlacementCheck` 61,601개와 `InventoryGridCheck` 759,784개 검사를 실행했습니다. 무효화→복사·부활 및 손에 든 배낭의 소유 슬롯 잠금·무기 추출·내용물 저장 회귀 검사는 GameTest로 작성하고 컴파일합니다. 실제 클라이언트나 GameTest 서버는 실행하지 않습니다.

배낭 겹침 수정 후 `InventoryGridCheck`는 기존 시작 칸과의 충돌·회전 충돌 검사를 포함해 759,788개를 통과했습니다. 배낭 화면 4곳에서 클릭·우클릭·숫자키 교환 거부, 기존 무기를 꺼낸 뒤 새 무기 배치, 소모품 합치기 회귀 검사를 추가하고 컴파일합니다. IFAK 최대 사용 횟수는 8회이며 1회 회복량 40은 유지합니다. `IfakMotionCheck`로 횟수 설정과 치료·취소·모션 시간을 확인했습니다.
